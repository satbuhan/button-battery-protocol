# Suspected or Witnessed Button Battery Exposure in a Child

An interactive, referenced walkthrough of the recognition and management pathway for
paediatric button battery exposure — ingestion, nasal insertion and aural insertion —
covering immediate first-aid actions, pre-removal mitigation (honey or sucralfate, only
within a strict age/time/ability-to-swallow window), biplane radiographs, a three-way
location fork (oesophagus; stomach or beyond the pylorus; nose or ear), each branch's own
emergency-removal, endoscopy, ENT-removal or observation pathway, and closing written
discharge safety-netting for the caregiver. Every box in the diagram can be selected to
reveal, in one place: what the step means, why the algorithm calls for it, and the sources
behind it.

**Live site:** https://satbuhan.github.io/button-battery-protocol/

**Authors:** Dr. Özgür Karcıoğlu & Dr. Satuk Buğra Han Bozatlı

## Why this exists

A flowchart alone tells a reader *what* to do at each step but not *why* — and button battery
exposure is a genuinely time-critical paediatric emergency where three separate professional
bodies (ESPGHAN, NASPGHAN and the National Capital Poison Center) partly agree and partly
diverge on thresholds and follow-up. This page keeps the original algorithm exactly as
authored, and attaches the clinical reasoning, the evidence certainty behind each step, and
the literature to each box without cluttering the diagram itself.

The algorithm this page presents is Figure 1 ("Original, author-developed pathway for the
recognition and management of button battery ingestion and insertion in children") of an
unpublished manuscript on paediatric button battery exposure — a SANRA structured narrative
review (PubMed/MEDLINE, January 2006 to October 2026; 433 records screened to 92 cited
references) — from a Gemini condensation of the manuscript text/tables plus the figure
supplied as a native-shapes PowerPoint slide (no embedded raster image).

## Status

This is a working version, built to be tested on both desktop and mobile.

- **Source workflow:** the manuscript's own narrative text, tables and 92-entry bibliography
  were condensed as usual by an external AI (Gemini) using this project's structured
  condensation prompt. Figure 1 had no embedded raster image to extract, so this build
  rendered the PowerPoint slide itself to a 300-DPI PNG (LibreOffice → PDF → `pdftoppm`) and
  read every box directly from that image, and separately tallied every `<a:solidFill>`
  colour in the slide's raw XML — rather than trusting the condensation's description alone.
- **Reference verification — explicit, author-granted exception (the seventh in this atlas):**
  asked directly whether to extend the same no-independent-re-verification policy used for
  `epinephrine-revisited-protocol`, `ketamine-indications-protocol`,
  `haloperidol-adjunct-protocol`, `geriatric-pain-protocol`,
  `metoclopramide-ondansetron-protocol` and `spontaneous-pneumothorax-protocol` to this tool's
  92-entry bibliography, the author confirmed the same policy again. The reference list was
  **not** independently re-verified against primary sources; every entry's `kind` field says
  so plainly. See `assets/content.js`'s header comment and `METHODOLOGY.md` for the full
  precedent record.
- **Condensation corrections, caught by reading the figure directly rather than trusting the
  automated extraction:**
  1. *Colour:* the condensation claimed the three branch headers (OESOPHAGUS / STOMACH OR
     BEYOND THE PYLORUS / NOSE OR EAR) were drawn in three different colours. A full tally of
     every fill colour in the slide's XML found only black and white anywhere on the slide —
     the figure is pure monochrome, and all three headers render identically here.
  2. *Missing arrow:* the condensation described "ENDOSCOPY" and "LOCAL PROTOCOL –
     ASYMPTOMATIC CHILD" as stacked with no connecting arrow. A zoomed crop of the rendered
     figure shows a clear, unambiguous arrow between them — modelled here as a real edge.
  3. *Merged text:* the condensation folded "A gastric position does not exclude oesophageal
     injury sustained in transit" into the asymptomatic-child box's own bullet list. The
     figure shows it is actually its own separate, solid-bordered box with its own arrows —
     modelled here as its own node.
  4. *Shape:* the condensation described the "WHERE IS THE BATTERY?" box as a rounded
     rectangle. The figure shows an unambiguous diamond decision shape — rendered with the
     atlas's existing decision-diamond style, same as every other tool.
- **A genuinely new rendering feature — border style as evidence-certainty coding:** the
  figure's own caption states that box border style carries meaning: solid = guideline-
  concordant core step; dashed ("LOW CERTAINTY") = preclinical evidence, case series or
  expert opinion; dotted ("LOCAL PROTOCOL") = guidance diverges or rests on a single source.
  This is the first tool in the atlas to encode evidence certainty as border style rather than
  colour/tone. See `METHODOLOGY.md` for how this is modelled.

## Disclaimer

This is an academic / educational reference tool, not a substitute for institutional protocol
or bedside clinical judgement. Doses and thresholds shown reflect the algorithm as authored;
verify against current local protocol before clinical use. This tool's reference list is
reproduced directly from the source manuscript's own bibliography and was not independently
re-verified for this build — see Status above.

## How it's built

Plain HTML/CSS/JS, no build step and no framework — a single static site that GitHub Pages
can serve directly.

```
index.html          page structure — masthead, border-style legend, the diagram (entry,
                     immediate actions + mitigation, radiographs, the three-way location
                     decision, oesophagus/stomach/nose-or-ear branches, discharge
                     safety-netting), readout panel, references, abbreviation legend, footer
assets/style.css     design (the "paper" masthead/references, the diagram grid, the new
                     certainty-border-style rules: solid/dashed/dotted)
assets/content.js    ← single source of truth for every node's text and reference list. Edit
                     this file to change what the page says.
assets/app.js        rendering + interaction (builds the diagram and its connector lines from
                     content.js, including a DETOUR-routed edge around the gastric-position
                     note box; handles the click-to-expand panel on desktop and the bottom
                     sheet on mobile)
```

### Running it locally

No install needed:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

### Editing content

Open `assets/content.js`. Each entry in `NODES` is one box from the diagram (`meaning`,
`rationale`, optional `dose`/`cautions`/`certainty`, and `refs` pointing at numbered entries
in `REFERENCES`). Add or edit a reference in `REFERENCES` and point to it by `id` from any
node. Never change a node's `label` or `sub` text without the author team's sign-off — those
fields are the algorithm itself, transcribed verbatim from the authors' own figure.
